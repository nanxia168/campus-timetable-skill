# ICS 生成的硬规则

这一页全部是实测踩出来的，不是规范抄写。**第 0 条尤其重要。**

## 0. 不要让语言模型手写 ICS

同一份课表，让模型直接输出 ICS，实测结果（43 行输出）：

| 问题 | 后果 |
| --- | --- |
| 用了 `<!-- 其余18条省略 -->` | iCalendar 没有注释语法，严格解析器整包报错，文件打不开 |
| 20 条事件只输出 2 条 | 这不是日历，是示例代码 |
| `RRULE:FREQ=WEEKLY;COUNT=13`，而描述写的是 `4-5,7-12,17-19周`（实为 11 周） | 多排 5 次、漏排 3 次 |
| 断周塞进一条 RRULE | 做不到，详见第 2 条 |
| 把 `TZID:Asia/Shanghai` 写在 `VCALENDAR` 层 | TZID 是**参数**不是属性，Google/Outlook 拒收 |
| 单行 123 octets 未折行 | 部分客户端截断或报错 |

**正确分工**：模型只产出 `courses.json`，ICS 由 `scripts/to_ics.py` 生成。模型擅长看懂图，不擅长逐字节合规。

## 1. 时间基准：`semester_start_date` 是第 1 周的**星期一**

错一周，整学期全错。实例：

- 校历第 1 周周一 = **2026-08-31**（不是 9/7，9/7 是第 2 周）
- 推算校验：第 3 周周三 = 2026-09-16，正好是"新生 9/16 正式上课"，对得上 → 说明基准取对了
- 若误取 9/7，所有事件晚 7 天，"开学第一课"会被排到 9/23

`to_ics.py` 会检查这个日期是不是星期一，不是就报错。

## 2. 断周必须拆成多条 VEVENT

一条 RRULE 只能表达"等差的周"，表达不了"断周"。

`4-5周, 7-12周, 17-19周` = 2 + 6 + 3 = **11 周**。写成一条 `COUNT=13` 会：

- 多排 5 次：第 6 周（国庆假期）、第 13–16 周（本来没课）
- 漏排 3 次：第 17–19 周
- 准确率 8/11 ≈ 73%，而且会跟同期其他课**撞车**（第 13–16 周周一被占，真正的课排不进去）

正确写法是三条：

```
DTSTART;TZID=Asia/Shanghai:20260921T083000  RRULE:FREQ=WEEKLY;COUNT=2   ← 第4-5周
DTSTART;TZID=Asia/Shanghai:20261012T083000  RRULE:FREQ=WEEKLY;COUNT=6   ← 第7-12周
DTSTART;TZID=Asia/Shanghai:20261221T083000  RRULE:FREQ=WEEKLY;COUNT=3   ← 第17-19周
```

## 3. 单双周用 `INTERVAL=2`

`3-19周(单)` = 9 个奇数周 → **一条**事件：

```
DTSTART;TZID=Asia/Shanghai:20260916T083000
RRULE:FREQ=WEEKLY;INTERVAL=2;COUNT=9
```

展开成 9 条单独的 VEVENT 也能用，但用户看到的是 9 个重复条目，体验差、改起来麻烦。

## 4. 时区：TZID 是参数

```
✅ DTSTART;TZID=Asia/Shanghai:20260916T083000
❌ TZID:Asia/Shanghai                     （写在 VCALENDAR 层，非属性）
❌ DTSTART:20260916T083000                （无 Z 无 TZID = 浮动时间，跨时区会偏）
```

并且必须自带 `VTIMEZONE` 块（中国无夏令时，`TZOFFSETFROM/TO` 均为 `+0800`）。

## 5. 折行与换行

- 每行 ≤ **75 octets**（字节，不是字符；中文一个字 3 字节）
- 超出用 `CRLF + 一个空格` 折行，**不能把一个 UTF-8 字符从中间劈开**
- 全文换行必须是 `CRLF`，纯 `LF` 会让部分客户端把整个文件读成一行

## 6. 必备属性

| 属性 | 为什么 |
| --- | --- |
| `UID` | 没有它，重复导入会产生重复条目。用 `课程号-星期-节次-首周@域名` 保证稳定 |
| `DTSTAMP` | 缺它部分客户端拒绝导入 |
| `SUMMARY` / `DTSTART` / `DTEND` | 基础三件套 |
| `LOCATION` | 没有地点就写"未标注"，比留空好——用户能看到"这里缺信息" |
| `VALARM`（`-PT10M`） | 课前提醒是这类工具的核心价值，别丢 |

## 7. 调休：截图是周模板，校历才是真相

课表只告诉你"第 6 周星期五有课"，但校历可能写着"10/9 按周三排课，10/10 按周五排课"。这时第 6 周星期五的课实际发生在**周六 10/10**。

用 `meta.day_shifts` 表达，不要把这种例外硬编码进脚本：

```json
{"code": "3573", "weekday": 5, "week": 6, "days": 1}
```

同理，补课日（如"9/20 按 10/5 周一排课"）截图里根本不会出现，只能靠校历补，或在 `assumptions` 里明确声明"未处理补课日"。

## 8. 怎么验证生成结果

```bash
python scripts/to_ics.py courses.json -o courses.ics --check
```

自检四件事：

1. **次数**：展开所有 RRULE 后，上课次数是否等于逐周算出来的数
2. **冲突**：任意两个事件时间不得重叠（分段周次可以互补，但真的重叠就是错）
3. **关键日期**：抽查"开学第一课""某门课首次""调休那天"三个日期
4. **行宽**：最长物理行是否 ≤ 75 octets

导入手机后再人工看一遍：开学第一周、国庆那一周、任意一个单周。

## 9. 一个容易忽略的坑

教室地点为空时，很多实现会直接丢掉 `LOCATION`。结果是用户看到一条"没有地点"的日程，以为是自己没填。写"未标注"更诚实。

## 10. 不要相信"位置"

教务系统排版时，如果两个课在同一时段但周次不重叠，会把其中一个块**往下挪两行**显示，而块里的文字仍然写着真实的"第1节-第2节"。

实测案例：某课文字写"第1节-第2节"，块画在第 3-4 行，模型按行位置输出了 `[3,4]`，并把 `confidence` 给到 0.9——**自信地错**。这是最危险的一类错误：用户不会去核。

校验办法：要求模型在 `note` 里抄录原文"第X节-第Y节"，再据此填 `periods`；两者不一致时 `confidence` 不得高于 0.5。
